## High

### Path traversal via caller-supplied `providedSlug`
- **File**: `src/pages/api/publish-note.ts:70`
- **Issue**: `const slug = providedSlug ?? slugify(title)` passes `providedSlug` directly into the GitHub file path (`src/content/notes/${slug}.md`) without sanitization. A caller who supplies `../../middleware` as `slug` would commit content to `src/middleware.md`; `../../../README` would overwrite `README.md`. The PUBLISH_API_KEY gate limits this to authorized callers, but a leaked or shared key turns it into an authenticated file-overwrite across the entire repo.
- **Fix**: Run `providedSlug` through `slugify()` (or validate against `/^[a-z0-9-]+$/`) before use, and reject any slug that differs from its sanitized form.

## Medium

### YAML injection in `buildFrontmatter` — single-quoted strings containing `'`
- **File**: `src/pages/api/publish-note.ts:23`
- **Issue**: When a field value contains a `"` the code falls back to single-quoting (`'${v}'`). If `v` also contains a `'` (e.g., `description: "Brady's note"`), the output is `description: 'Brady's note'` — invalid YAML. This breaks Astro content collection parsing for that file, making the note inaccessible or causing a build failure.
- **Fix**: Escape single quotes inside single-quoted YAML strings by doubling them (`'` → `''`), or use a proper YAML serializer (e.g., `JSON.stringify` for string scalars, which is always valid YAML for scalars that don't need anchors).

### No size or format validation on request body fields
- **File**: `src/pages/api/publish-note.ts:62`
- **Issue**: `title`, `content`, `description`, and `tags` are accepted without length or element-count limits. A caller can submit a `content` field of arbitrary size (megabytes), which is buffered in memory and then committed as a file to GitHub. GitHub will reject files over 100 MB via the API, but the server still buffers and attempts the call.
- **Fix**: Add a reasonable max length check for each field (e.g., `content` ≤ 500 KB, `title` ≤ 200 chars, `tags.length` ≤ 20). Return a 400 immediately if exceeded.

## Low

### `sign()` exported from middleware — unnecessarily widens the signing surface
- **File**: `src/middleware.ts:76`
- **Issue**: `sign()` is a raw HMAC primitive that wraps `crypto.subtle.sign` with the deployment's `TRIP_SECRET`. Exporting it (alongside `COOKIE_NAME`) makes it available to any importer, broadening the surface that touches the secret. Currently only `auth.ts` needs it.
- **Fix**: Unexport `sign()` and move it to `src/lib/auth.ts` shared by both `middleware.ts` and `auth.ts`, keeping it internal to the auth layer.

### Voter names from Redis not validated against the allow-list
- **File**: `src/pages/api/trips/votes.ts:38`
- **Issue**: The voter name extracted from each Redis hash field (`field.slice(sep + 1)`) is included in the response without checking it against `VOTERS`. Manually-written or corrupted entries in Redis with unexpected voter strings would leak into the API response.
- **Fix**: After extracting `voter`, call `isVoter(voter)` (already exported from `redis.ts`) and `continue` if false.

### In-process rate-limit fallback counter grows unbounded
- **File**: `src/pages/api/trips/auth.ts:17`
- **Issue**: `fallbackCounts` is a module-level `Map`. Expired entries are only evicted lazily when the same IP makes a follow-up request. Under adversarial scanning with many source IPs, the map will grow until the serverless function's process is recycled, consuming memory that could be used by legitimate requests.
- **Fix**: Add a periodic sweep or cap the map size (e.g., evict the oldest entry when size exceeds 1 000). A simple `setTimeout`-based cleanup on each write also works.
