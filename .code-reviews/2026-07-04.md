## High

### Path traversal in user-supplied slug allows arbitrary file writes via GitHub API
- **File**: `src/pages/api/publish-note.ts:70`
- **Issue**: `providedSlug` is taken directly from the request body and concatenated into the GitHub API path without any sanitization. A caller who supplies `slug: "../../astro.config"` gets a GitHub PUT to `src/content/notes/../../astro.config.md`, which GitHub resolves to `astro.config.md` in the repo root, overwriting that file. Any `.md` file in the repo is reachable this way with a valid `PUBLISH_API_KEY`.
- **Fix**: Apply the same `slugify()` transformation to `providedSlug`, or validate it with `/^[a-z0-9][a-z0-9-]*[a-z0-9]$/` before use. Never trust the caller-supplied slug as a path component.

## Medium

### YAML frontmatter builder produces invalid YAML when a value contains both `'` and `"`
- **File**: `src/pages/api/publish-note.ts:22-27`
- **Issue**: `buildFrontmatter` wraps strings that contain `"` in single quotes (e.g., `title: 'It's "great"'`). If the value also contains a single quote (e.g., a title like `It's a "great" day`), the output is syntactically invalid YAML. Astro's content collection parser will throw on the next build, breaking the entire site until the bad file is manually removed from the repo.
- **Fix**: Use a proper YAML scalar serializer — either `JSON.stringify(v)` for double-quoted scalars with all special chars escaped, or a minimal YAML escape function that handles both `"` and `'`. Since frontmatter values are strings, double-quoted with `"` escaped as `\"` covers all cases: `` `${k}: ${JSON.stringify(v)}` ``.

### Non-atomic INCR + EXPIRE in rate limiter can permanently lock out an IP
- **File**: `src/pages/api/trips/auth.ts:24-25`
- **Issue**: `redis.incr(key)` and `redis.expire(key, WINDOW_SEC)` are two separate round-trips. If the process or connection dies between them (or if `expire` returns an error that is not explicitly caught), the key persists in Redis indefinitely. After 5 login attempts, that IP is permanently locked out — there is no TTL to reset the window.
- **Fix**: Replace the two-call pattern with a Lua script or use `SET key 0 EX 60 NX` to atomically initialize the key with a TTL, then `INCR`:
  ```ts
  await redis.set(key, 0, { ex: WINDOW_SEC, nx: true });
  const count = await redis.incr(key);
  return count <= MAX_ATTEMPTS;
  ```

## Low

### `PUBLISH_API_KEY` and `GITHUB_TOKEN` missing from `ImportMetaEnv`
- **File**: `src/env.d.ts:1-10`
- **Issue**: The env type declarations include `TRIP_SECRET`, `TRIP_PIN`, and the Redis vars, but omit `PUBLISH_API_KEY` and `GITHUB_TOKEN`. TypeScript cannot catch typos in these identifiers at build time; a misspelling silently produces `undefined` and the endpoint fails at runtime with a confusing 500/401.
- **Fix**: Add `readonly PUBLISH_API_KEY: string;` and `readonly GITHUB_TOKEN: string;` to the `ImportMetaEnv` interface.
