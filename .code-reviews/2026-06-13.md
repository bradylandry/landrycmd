## High

### Path traversal via `providedSlug` in publish-note API
- **File**: `src/pages/api/publish-note.ts:70-73`
- **Issue**: When a caller supplies an explicit `slug` in the request body, it is used directly to build the GitHub file path (`src/content/notes/${slug}.md`) with no sanitization. A crafted slug like `../../package.json` resolves to `package.json` at the repo root, allowing an authenticated caller (valid `PUBLISH_API_KEY`) to overwrite any file in the repository — including source files, config, and API routes.
- **Fix**: Reject any `providedSlug` that differs from its own `slugify()` result, or validate it against `/^[a-z0-9-]+$/` before use:
  ```ts
  const slug = slugify(providedSlug ?? title);
  if (!slug || !/^[a-z0-9-]+$/.test(slug)) {
    return new Response(JSON.stringify({ error: "Invalid slug" }), { status: 400 });
  }
  ```

## Medium

### Invalid YAML output for strings containing both quote types
- **File**: `src/pages/api/publish-note.ts:18-31`
- **Issue**: `buildFrontmatter` wraps strings in double quotes by default but switches to single quotes when the value contains `"`. If a value contains **both** `"` and `'` (e.g. `title: I said "hello" and it's fine`), the output becomes `title: 'I said "hello" and it's fine'` — a single-quoted YAML string with an unescaped single quote. This is invalid YAML and will cause Astro's build to fail, silently dropping newly published notes until the bad file is corrected. The tags array branch (`"${s}"`) has the same problem for tags containing `"`.
- **Fix**: Use a proper YAML serializer (`js-yaml` / `yaml` npm package), or at minimum escape single quotes in single-quoted strings by doubling them: `v.replace(/'/g, "''")`).

### Missing env var declarations in `env.d.ts`
- **File**: `src/env.d.ts:1-10`
- **Issue**: `PUBLISH_API_KEY` and `GITHUB_TOKEN` are consumed via `import.meta.env` in `publish-note.ts` but are not declared in the `ImportMetaEnv` interface. TypeScript types them as `any`, meaning typos in env var names in that file won't produce a compile error.
- **Fix**: Add the two missing declarations to `ImportMetaEnv`:
  ```ts
  readonly GITHUB_TOKEN: string;
  readonly PUBLISH_API_KEY: string;
  ```

## Low

### Non-constant-time HMAC comparison
- **File**: `src/middleware.ts:26`
- **Issue**: `verifyToken` compares the computed HMAC against the submitted signature with `expected !== sig` (JavaScript string equality), which is not constant-time and is theoretically vulnerable to timing side-channels that could help an attacker forge a valid token. For the current use case (private family trip app, short-lived tokens), practical risk is negligible.
- **Fix**: Replace with a constant-time comparison using `crypto.subtle.timingSafeEqual` on the encoded buffers if a future use-case raises the threat model.
