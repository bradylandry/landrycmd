## High

### Path traversal via unsanitized `providedSlug` in publish-note.ts
- **File**: `src/pages/api/publish-note.ts:70`
- **Issue**: When the request body includes a `slug` field, it is used verbatim to construct the GitHub file path: `` filePath = `src/content/notes/${slug}.md` ``. The `slugify()` function is only applied when `providedSlug` is absent. An authenticated caller (anyone who holds `PUBLISH_API_KEY`) can pass a value like `../../layouts/Layout` to write a file to `src/layouts/Layout.md`, or `../../middleware` to create `src/middleware.md`, writing arbitrary `.md` files anywhere in the repo tree. The GitHub Contents API accepts relative path segments, so traversal outside `src/content/notes/` is possible.
- **Fix**: Apply the same `slugify` transformation unconditionally regardless of whether a slug was provided, or add an explicit allowlist check (e.g., `/^[a-z0-9][a-z0-9-]*[a-z0-9]$/.test(slug)`) that rejects any slug containing `/`, `.`, or other non-slug characters before constructing `filePath`.

## Medium

### YAML injection via unescaped newlines in `buildFrontmatter`
- **File**: `src/pages/api/publish-note.ts:18-32`
- **Issue**: `buildFrontmatter` wraps string values in double or single quotes based on whether the value contains `"`. It does not escape or reject embedded newlines (`\n`). A `title` value of `"legit title\ndraft: false"` would render as:
  ```
  title: "legit title
  draft: false"
  ```
  which most YAML parsers interpret as `title: "legit title"` followed by a bare `draft: false` key at the top level, overriding the actual frontmatter field. Additionally, values containing both `"` and `'` (e.g., `it's a "great" post`) produce broken YAML: `` title: 'it's a "great" post' `` — the embedded `'` closes the quoted scalar early. A description containing `---` on its own line would also prematurely close the frontmatter block.
- **Fix**: Replace the ad-hoc quoting logic with a proper YAML scalar serializer. At minimum, strip or reject any string value that contains `\n`, `\r`, or `---`, and escape all `'` in single-quoted scalars (doubling them per YAML spec) or use folded/literal block scalars for multiline-safe encoding.

### `GITHUB_TOKEN`, `GITHUB_REPO`, and `PUBLISH_API_KEY` missing from `ImportMetaEnv`
- **File**: `src/env.d.ts:1-11`
- **Issue**: `publish-note.ts` reads `import.meta.env.GITHUB_TOKEN`, `import.meta.env.GITHUB_REPO`, and `import.meta.env.PUBLISH_API_KEY` but none of these are declared in the `ImportMetaEnv` interface in `src/env.d.ts`. TypeScript treats them as `any`, so a typo or accidental deletion of a variable name goes undetected at compile time. The existing `TRIP_SECRET`, `TRIP_PIN`, and Redis vars are properly declared.
- **Fix**: Add the three missing declarations to `ImportMetaEnv`:
  ```ts
  readonly GITHUB_TOKEN: string;
  readonly GITHUB_REPO: string;
  readonly PUBLISH_API_KEY: string;
  ```

### `nyc-2026.astro` relies on JS to set `target="_blank"` on chip links; `starbase-2026.astro` sets it in the template
- **File**: `src/pages/trips/nyc-2026.astro:1588-1596`
- **Issue**: External chip links on the NYC page have `target="_blank"` and `rel="noopener noreferrer"` applied after the fact by a client-side script. During the brief window between HTML parse and script execution, external links open in the same tab. The Starbase page hard-codes `target="_blank" rel="noopener"` in the Astro template, which is the more robust pattern. This is a minor UX inconsistency rather than a security issue (`rel` is populated before any user interaction is possible in practice).
- **Fix**: Add `target="_blank" rel="noopener noreferrer"` directly to chip `<a>` elements in the NYC page Astro template for external URLs, matching the Starbase page's approach.
