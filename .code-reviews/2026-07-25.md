## High

### Path traversal via unsanitized `providedSlug` in publish-note API
- **File**: `src/pages/api/publish-note.ts:70`
- **Issue**: `slug` is derived from the caller-supplied `body.slug` with zero sanitization before being interpolated into `filePath = \`src/content/notes/${slug}.md\``. A caller who knows `PUBLISH_API_KEY` can pass `../../../.github/workflows/pwned` as the slug, causing the GitHub Contents API PUT to write to an arbitrary path in the repo (e.g. injecting a CI workflow file). The auto-generated path via `slugify()` is safe, but the `providedSlug ?? slugify(title)` short-circuit completely bypasses it.
- **Fix**: Reject or sanitize `providedSlug` before use. A one-liner: `if (providedSlug && !/^[a-z0-9-]+$/.test(providedSlug)) return 400;`. Alternatively, run the provided slug through `slugify()` as well, which strips path separators.

### INCR/EXPIRE race condition can permanently lock out an IP
- **File**: `src/pages/api/trips/auth.ts:24-25`
- **Issue**: The rate-limiter increments the counter and then sets the TTL in a separate call:
  ```ts
  const count = await redis.incr(key);
  if (count === 1) await redis.expire(key, WINDOW_SEC);
  ```
  If the `expire` call fails (network blip, Upstash timeout) on the very first request from an IP, the key is written with no TTL. It persists indefinitely, so after 5 total login attempts spread over any time period the IP is permanently locked out with no recovery path other than manual key deletion.
- **Fix**: Replace the two-call pattern with a single atomic operation. Use a Lua script or `SET key 0 EX 60 NX` + `INCR` in a pipeline. For Upstash's `@upstash/redis`, the simplest fix is a small Lua eval:
  ```ts
  const count = await redis.eval(
    `local n = redis.call('INCR', KEYS[1])
     if n == 1 then redis.call('EXPIRE', KEYS[1], ARGV[1]) end
     return n`,
    [key], [String(WINDOW_SEC)]
  ) as number;
  ```

## Medium

### `buildFrontmatter` produces invalid YAML for strings containing both quote types
- **File**: `src/pages/api/publish-note.ts:23-30`
- **Issue**: The function wraps strings in single quotes when they contain a double quote, but does not escape single quotes within the value. A title like `Brady's "best" post` would generate `title: 'Brady's "best" post'` — the apostrophe breaks YAML parsing. Array tag items are also interpolated raw inside double quotes without escaping, so a tag containing `"` would break the inline array.
- **Fix**: Use proper YAML escaping. For the string case, either escape inner single quotes (`v.replace(/'/g, "''")`) or always double-quote and escape double quotes (`v.replace(/"/g, '\\"')`). For the array case, apply the same escaping to each tag. Alternatively, import a small YAML serialiser (e.g. `js-yaml`'s `dump()`) for the frontmatter block instead of hand-rolling it.

### `GITHUB_TOKEN`, `GITHUB_REPO`, and `PUBLISH_API_KEY` absent from `ImportMetaEnv`
- **File**: `src/env.d.ts:1-10`
- **Issue**: `env.d.ts` declares the trip-related vars but omits `GITHUB_TOKEN`, `GITHUB_REPO`, and `PUBLISH_API_KEY`. These are accessed via `import.meta.env` in `publish-note.ts`, so TypeScript treats them as `any` and won't catch typos or missing-env issues at compile time.
- **Fix**: Add the three missing entries:
  ```ts
  readonly GITHUB_TOKEN: string;
  readonly GITHUB_REPO: string;
  readonly PUBLISH_API_KEY: string;
  ```

### `VOTE_KEY` hard-coded to the NYC 2026 trip
- **File**: `src/lib/redis.ts:30`
- **Issue**: `export const VOTE_KEY = "trip:nyc-2026:votes"` is a module-level constant. When a future trip page needs its own voting namespace, both `redis.ts` and any new vote route will need to be updated or the new route risks sharing/colliding with the NYC key. The voters list is similarly NYC-specific.
- **Fix**: Accept the trip identifier as a parameter in the helpers, or derive the key from the trip slug passed at call-site. A light approach: export a factory `voteKey(tripId: string) => \`trip:${tripId}:votes\`` and update vote/votes routes to pass their trip slug.
