## Critical

### HMAC verification accepts empty-string secret — API routes bypassable when TRIP_SECRET is unset

- **File**: `src/middleware.ts:7`, `src/pages/api/trips/vote.ts:9`, `src/pages/api/trips/votes.ts:9`
- **Issue**: `const SECRET = import.meta.env.TRIP_SECRET || ""` falls back to an empty string. The middleware's guard (`if (!SECRET) return 500`) only fires on `/trips/*` page routes — it never runs for `/api/trips/*` routes, which call `verifyToken` directly. HMAC-SHA256 with an empty key is still a valid, computable HMAC. Anyone who reads the public source can precompute `HMAC-SHA256("", payload)` for an arbitrary future expiry and present a token that passes `verifyToken`. The auth endpoint blocks new token issuance when SECRET is empty, but it doesn't revoke the ability to forge them.
- **Fix**: Add a guard at the top of `verifyToken` that returns `false` immediately when `SECRET` is empty:
  ```ts
  export async function verifyToken(token: string): Promise<boolean> {
    if (!SECRET) return false;
    // ... rest of function
  }
  ```
  This is a one-line fix that closes the bypass without changing the token format.

## High

### Rate-limit buckets collapse when `clientAddress` is `"unknown"`

- **File**: `src/pages/api/trips/auth.ts:26`
- **Issue**: `const ip = clientAddress || "unknown"` means that in any Vercel deployment where the edge runtime doesn't populate `clientAddress` (e.g. certain proxy or regional configurations), every request shares the key `ratelimit:auth:unknown`. Five failed auth attempts from any user — or any test run — would lock out all users for the 60-second window. Conversely, an attacker who can arrange requests from distinct IPs in a shared-IP environment bypasses the rate limit entirely.
- **Fix**: Log a warning when `clientAddress` is absent and consider a secondary key (e.g. hash of `User-Agent + X-Forwarded-For` as a fallback) or fail open with a stricter global cap rather than a per-IP one. At minimum, log `clientAddress` at the time of rate limit hit so the failure mode is visible in Vercel logs.

## Medium

### Stale `VOTE_KEY` constant mixes data across trips

- **File**: `src/lib/redis.ts:24`
- **Issue**: `export const VOTE_KEY = "trip:nyc-2026:votes"` is the only vote storage key and is used by both `vote.ts` and `votes.ts` for every trip, including Starbase 2026. If `optionId` slugs from different trips ever collide (e.g. both have a `"day-1"` option), their votes will silently merge into the same hash fields.
- **Fix**: Either parameterize the key by trip slug (`trip:${slug}:votes`) and pass the slug from the page, or at minimum rename the constant to `VOTE_KEY = "trip:starbase-2026:votes"` now that NYC is no longer active. If multiple trips will coexist, keying by trip ID is the right fix.

## Low

### `post.slug` is deprecated in Astro 4+ content collections

- **File**: `src/pages/rss.xml.ts:17`
- **Issue**: `link: \`/writing/${post.slug}/\`` uses the deprecated `slug` property on content collection entries. Astro 4.x still supports it but Astro 5 removed it in favor of `post.id` (which drops the file extension). Leaving this as-is will require a fix during the next major Astro upgrade.
- **Fix**: Replace `post.slug` with `post.id` and strip any `.md`/`.mdx` extension if needed, or use `post.id.replace(/\.[^.]+$/, "")`. Update once on the Astro 5 migration.
