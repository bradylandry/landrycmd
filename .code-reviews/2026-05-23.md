## High

### Rate limiter fails open on Redis unavailability
- **File**: `src/pages/api/trips/auth.ts:18-20`
- **Issue**: `checkRateLimit` returns `true` (allow) when Redis is unavailable, with only a console warning logged. The auth endpoint protects a 4-digit PIN (10,000 combinations). Without rate limiting, an attacker can exhaust all combinations in seconds from a single IP. The fail-open behavior means a Redis outage — even a transient one — silently removes the only brute-force protection.
- **Fix**: Fail closed: return `false` (deny) when Redis is unavailable, and return a 503 to the caller. Accept the UX cost of blocking auth during Redis outages rather than exposing unlimited guesses. If you need high availability for auth, consider an in-memory fallback with a short TTL that survives only the lifetime of the function instance.

## Medium

### `voteId` not declared in `DayEvent` TypeScript interface
- **File**: `src/pages/trips/nyc-2026.astro:87`
- **Issue**: The `DayEvent` interface defines `time`, `title`, `detail?`, `votable?`, and `actions?`, but 12 event object literals across the `days` array assign a `voteId` property (e.g., `voteId: "tue-insomnia"` at line 142). TypeScript's excess property check on `events: DayEvent[]` should flag these as errors. Either the build is silently discarding type errors, or `voteId` values are being silently dropped at runtime and the voting feature may not work correctly end-to-end if the template reads `event.voteId` later.
- **Fix**: Add `voteId?: string` to the `DayEvent` interface. Run `npx astro check` to surface any suppressed type errors and resolve them.

### Non-atomic read-modify-write in vote toggle
- **File**: `src/pages/api/trips/vote.ts:67-74`
- **Issue**: The toggle action (`action === "toggle"`) reads the current vote state from Redis, then conditionally writes or deletes in two separate commands. Two concurrent toggle requests from the same voter can both read a "no vote" state and both write `"1"`, or both read `"1"` and both delete — leaving state inconsistent with user intent.
- **Fix**: Replace the read-then-write with an atomic Lua script or a Redis GETSET approach. Alternatively, move to explicit `set`/`unset` actions from the client (eliminating the toggle entirely), which removes the race condition by design. Given that the client UI could track its own optimistic state and send explicit set/unset, this may be the simpler fix.

### No custom env var types declared in `env.d.ts`
- **File**: `src/env.d.ts:1`
- **Issue**: The file contains only the Astro reference path. Environment variables `TRIP_SECRET`, `TRIP_PIN`, `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`, `KV_REST_API_URL`, and `KV_REST_API_TOKEN` are accessed via `import.meta.env.*` throughout the codebase but are not declared in `ImportMetaEnv`. TypeScript can't warn at compile time when they're missing or misspelled.
- **Fix**: Add the declarations:
  ```ts
  interface ImportMetaEnv {
    readonly TRIP_SECRET: string;
    readonly TRIP_PIN: string;
    readonly UPSTASH_REDIS_REST_URL: string;
    readonly UPSTASH_REDIS_REST_TOKEN: string;
  }
  ```
